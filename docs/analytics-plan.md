# 客户后台「站点数据」升级方案

目标：让客户老板打开后台一眼看懂网站的流量从哪来、哪个市场在增长、AI 带来了多少访客、哪些渠道和页面带来询盘，并且每个数字都能和上一周期对比。在 Vercel Analytics 的流量维度之上，补齐我们独有的 GEO 闭环：**流量 → AI 来源 → 线索 → 跟进结果**，再关联 AI 可见性测评。

## 指标口径

| 指标 | 定义 |
|---|---|
| 访客 | visitor_id 去重（采集脚本存在访客浏览器 localStorage 的随机 ID） |
| 浏览量 | 页面被打开的次数（单页应用切换路由也算） |
| 会话 | 同一访客连续访问，30 分钟无操作，或带着站外来源 / 广告参数重新进站，算新会话 |
| 跳出率 | 只看了 1 页、参与时长不到 10 秒且没有留资的会话 ÷ 会话 |
| 平均参与时长 | 每次会话中页面停留在前台的平均时长（切到其他标签页不计） |
| 留资转化率 | 留下线索的访客 ÷ 访客 |
| 环比 | 与紧挨着的等长上一周期比较；计数类给相对变化，比率类给百分点差 |
| 渠道 | 直接访问 / 自然搜索 / AI 助手 / 社交媒体 / 外部链接 / 付费广告 / 邮件，规则见 `src/server/channels.ts` |
| 线索来源 | 留资所在的会话不是直接访问时用它，否则取 90 天内最近一次非直接访问的会话 |

升级前的访问没有会话，只计入访客与浏览量。上一周期含这类访问时，会话类指标（跳出率、时长、渠道、地区等）不做环比，页面上显示「暂无可比数据」。

## 分期

### 一期（已完成）

- 采集：会话 ID、参与时长与滚动深度（页面切到后台 / 关闭时 sendBeacon 补报）、浏览器语言、UTM 与广告点击 ID、排除自己的访问（`?cw_ignore=1`）；服务端识别渠道、来源、国家与省州（Vercel 请求头，不存 IP）、浏览器、系统，过滤爬虫与自动化工具；入库路径去掉查询串。
- 数据：迁移 `005_analytics_v2.sql`（`visits` 加会话与参与时长、新建 `visit_sessions`、`leads` 加来源快照）。
- 接口：`/stats` 返回当前与上一周期的核心指标和两段每日序列；`/stats/breakdown` 按维度拆分（带上期访客数）。
- 页面：数据概览改版，包括 6 个带环比与迷你趋势的指标卡、叠加上一周期的趋势图、来源渠道 / 来源 / 活动、AI 来源、国家与语言、热门页面 / 入口页 / 退出页、设备 / 浏览器 / 系统；线索列表、详情与 CSV 增加来源、落地页与国家。

### 二期

- 「流量分析」页：维度标签页 + 点击任意行加为全局筛选（可叠加），支持导出。
- 事件：`CloudWise.track(name, props)`，自动记录 `mailto:`、`tel:`、WhatsApp、外链与文件下载点击，计入询盘与转化。
- 「转化分析」页：访客 → 浏览 2 页以上 → 访问联系 / 产品页 → 询盘 → 已联系 → 有意向 → 成交的漏斗；按渠道、国家、落地页归因；平均首次跟进时长（需记录状态变更时间）。
- 实时在线（近 5 分钟）、按小时粒度、自定义时间范围、站点时区设置。
- 「本期要点」：先用确定性规则（涨跌最大的渠道 / 国家 / 页面、流量大但跳出率高的页面、连续 24 小时没收到数据的接入提醒）生成。

### 三期

- Web Vitals（LCP、INP、CLS）按页面与设备统计。
- AI 爬虫抓取日志：爬虫不执行 JS，需要服务端中间件，只适用于我方托管（`hosting = 'vercel'`）的站点。
- AI 可见性测评分数趋势（`sites.domain` 关联 `audits.target_key`）放进「AI 来源」。
- 每周邮件报告；数据量大后加每日汇总表与原始数据保留期；免 Cookie / 同意模式（GDPR）。

## 待确认

- 城市级数据：目前只存国家与省 / 州。
- `leads.ip` 仍保存原始 IP，与「不存 IP」的对外口径不完全一致，可改为只保留国家或 /24 前缀。
- AI 来源是否作为 GEO 服务的卖点，对未购买 GEO 服务的客户只显示简版。
